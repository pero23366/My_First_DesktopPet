你没懂很正常，这段在说：**`type="module"` 不是只多了一个属性，而是让浏览器把 `<script>` 当成“模块脚本”来对待，规则和普通脚本不一样。** 所谓“副作用”不是贬义，是“顺带产生的行为变化”。

先对比一下：

```html
<!-- 普通脚本 -->
<script src="/main.js"></script>

<!-- 模块脚本 -->
<script type="module" src="/main.js"></script>
```

普通脚本和模块脚本，浏览器对它们的处理方式不同。

---

## ① 自动 defer：执行时机变了

普通脚本默认是“阻塞”的：

```html
<script src="/main.js"></script>
<div id="app"></div>
```

浏览器解析 HTML 时，遇到这个脚本会先停下来，下载并执行 `main.js`，然后才继续解析后面的 `<div id="app">`。所以如果 `main.js` 里写：

```js
document.querySelector('#app')
```

可能拿不到，因为 `#app` 还没被解析出来。

模块脚本默认类似加了 `defer`：

```html
<script type="module" src="/main.js"></script>
<div id="app"></div>
```

它的行为是：

- 下载 `main.js` 时，**不阻塞 HTML 解析**；
- 等 HTML 解析完，再执行 `main.js`；
- 执行时机在 `DOMContentLoaded` 之前。

所以 `main.js` 里可以直接写：

```js
document.querySelector('#app')
```

因为执行时 DOM 已经建好了，不用再写：

```js
document.addEventListener('DOMContentLoaded', () => {
  document.querySelector('#app')
})
```

注意：不是“等 HTML 解析完才下载”，而是“下载可以并行，执行等到解析完”。这是很多人容易误解的点。

---

## ② 独立作用域：变量不再挂到 `window` 上

普通脚本里：

```html
<script>
  var a = 1
  function fn() {}
</script>
```

`a` 和 `fn` 会成为全局变量，等价于：

```js
window.a // 1
window.fn // function
```

多个普通脚本之间容易互相污染：

```html
<script>
  var name = 'A'
</script>
<script>
  var name = 'B' // 覆盖了上面的
</script>
```

模块脚本不一样：

```html
<script type="module">
  var a = 1
  function fn() {}
</script>
```

模块有自己的顶层作用域：

```js
window.a  // undefined
window.fn // undefined
```

每个模块文件像一个独立房间，里面的变量默认不跑到 `window` 上。多个模块里都写 `const name = ...` 也不会互相覆盖。

但注意：不是完全不能暴露，你显式写：

```js
window.a = 1
```

还是可以的。

另外模块顶层 `this` 是 `undefined`，普通脚本顶层 `this` 是 `window`，这也是作用域规则变化的一部分。

---

## ③ 支持 `import` / `export`：可以拆文件了

普通脚本里直接写：

```js
import { add } from './math.js'
```

浏览器会报错，因为它不按模块解析。

模块脚本可以：

```js
// math.js
export function add(a, b) {
  return a + b
}
```

```js
// main.js
import { add } from './math.js'
console.log(add(1, 2))
```

```html
<script type="module" src="/main.js"></script>
```

浏览器会自己处理依赖关系：先加载 `math.js`，再执行 `main.js`。

这就是原文说的“拆文件的入场券”：**没有 `type="module"`，就不能在浏览器里直接用 `import/export` 拆模块。** 以前要靠 Webpack、Vite 等打包工具处理，现在浏览器原生支持了。

---

## 另外：自动开启严格模式

模块脚本自动相当于：

```js
'use strict'
```

一些普通脚本里“静默出错”的写法，在模块里会直接报错。比如：

```js
x = 1 // 没声明就赋值
```

普通脚本可能悄悄创建全局变量，模块脚本直接报 `ReferenceError`。

---

## 一句话总结

`<script type="module">` 改的是浏览器对脚本的**解析和执行规则**：

| 变化 | 通俗解释 |
|---|---|
| 自动 defer | 先解析 HTML，解析完再执行脚本，所以能直接查 DOM |
| 独立作用域 | 每个模块文件有自己的变量空间，不污染 `window` |
| 支持 import/export | 可以把代码拆成多个文件互相引用 |
| 自动严格模式 | 写错更容易直接报错，而不是悄悄出错 |

所以原文说的“三个副作用 + 严格模式”，本质就是：**普通脚本是“老式全局脚本”，模块脚本是“独立、延迟执行、可互相引用、更严格”的脚本。** 你项目里 `main.js` 能直接 `querySelector`，就是因为第一条：它默认 defer，执行时 DOM 已经好了。
