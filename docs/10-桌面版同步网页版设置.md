# 10 · 桌面版同步网页版设置（源码并入仓库）

> 一句话：网页版这两周长出来的四段设置，桌面版全部跟上了；顺手把桌面版源码搬进了仓库。
> 对应网页版功能见 `record/Solution/桌宠对话优化.md`。

## 一、为什么这次要动桌面版

网页版在 10/20 做完了四条改动：

1. 设置面板有关闭键
2. 对话框有关闭键
3. 自动收起的 10 秒常量，改成 10~60 秒可调
4. 默认不收起

桌面版当时的状态是「半迁移」：`PetSettings.cs`、`WebPetConfig.cs`、`DefaultPersona.cs` 三个文件已经写好，
但 `MainWindow.xaml.cs` **一个都没用上**——还在读 `apikey.txt`，人设那段几百字的文本在同一个文件里复制了三遍，
自动收起写死成 10 秒（reasoner 模式 20 秒），也没有任何关闭键。

也就是说，那三个文件是"备好了料但没下锅"。这次就是把锅端上去。

## 二、四条需求在桌面版怎么落地

| 网页版 | 桌面版做法 | 差异原因 |
|---|---|---|
| 设置面板 ✕ | 独立窗口 + 标题栏关闭键 + **Esc 关窗口** | 桌面用独立窗口比浮层自然；Esc 必须先关设置窗，否则按一下就把桌宠退了 |
| 对话框 ✕ | 气泡右上角 20×20 的 ✕，点了就收 | 与网页同逻辑：只藏气泡，输入行保留，再发一句话自动回来 |
| 10~60 秒滑条 | `Slider` 10~60，`IsSnapToTickEnabled` 步进 5，未勾选时置灰 | 与网页同一区间、同一步进 |
| 默认不收起 | `PetSettings.AutoHideEnabled` 默认 `false` | 与网页同一条规则 |

另外把网页版需求 5 的那句警示语**一个字不改**抄了过来：
「注意，网页版如果选了此项，对话消失后，不可找回！！！」
未开启时灰色，勾上后转琥珀色——和网页版同一套判断。

## 三、顺带修掉的三个结构问题

1. **人设文本 3 份 → 1 份**
   `MainWindow.xaml.cs` 里那段人设原来在"读历史命中 / 读历史未命中 / 插入人设"三处各复制一遍，
   改一句台词要改三个地方，必然改漏。现在只留 `DefaultPersona.Prompt`，其余全删。

2. **Key 的存放从 `apikey.txt` 换成 `pet_settings.json`**
   `PetSettings.Load()` 里有一次性迁移：发现旧文件且 json 里没 Key 就搬过去，把旧文件改名 `.bak` 留底。
   这样之前填过 Key 的人升级后不用重填。

3. **帧间补偿从来没生效**
   原代码有 `double[] idleScales = { 1.0, 0.1, 0.1 };` 这个数组，但从没被用过（写对了也不会有效，0.1 明显是占位）。
   现在用网页版实测的不透明包围盒数值：帧 2 `scale 0.905 / 平移(-1.3%, +3.8%)`，帧 3 `scale 0.943 / (-2.1%, +2.3%)`，
   通过 `TransformGroup`（Scale + Translate）实现，切换时不再"跳一下"。

## 四、源码为什么搬进仓库

桌面版源码原来在 `D:\code\项目\工具\AI桌宠_V1.0.0`，**不在 git 仓库里**。
这意味着不管改多少，GitHub 上永远只有那个 59MB 的 zip——源码本身没有任何版本记录。

处理方式（三步，都可逆）：

1. 源码复制进仓库 `desktop/`（去掉 `bin`、`obj`、`.vs`、`.csproj.user`）
2. 原目录改名为 `AI桌宠_V1.0.0.bak-20261021` 留底
3. 原路径改成**目录联接**指向 `desktop/`

第 3 步是关键：老路径 `D:\code\项目\工具\AI桌宠_V1.0.0` 打开的还是同一份文件，
VS 的最近项目、`publish-desktop.ps1`、任何绝对路径都不需要改。**一份源码，两个入口。**

`tools/publish-desktop.ps1` 的默认 `ProjectPath` 也改成了仓库内的 `..\desktop`，
以后打包不再依赖 D 盘那个路径。

## 七、还缺什么（没做，写下来免得忘）

- **Key 是明文存的**：`pet_settings.json` 里能直接读到。桌面版需要跨重启记住 Key，
  正确的做法是用 Windows DPAPI（`ProtectedData.Protect`，密钥绑当前账户）。
  这需要一个 NuGet 包 `System.Security.Cryptography.ProtectedData`，这次没加，界面上也把"加密"两个字去掉了，不误导人。
- **桌面版没有导出 .pet.json**：它是导入端。真要双向同步，得在设置里加一个"导出"。
- **气泡里只有一条消息**：桌面版是一问一答式，不像网页版有可滚动的对话列表。这是形态差异，不是漏做。

## 八、第 7 条：历史记录 + 记忆压缩

### 一个必须先讲清的矛盾

用户要三件事，它们天生互相打架：

1. 能看到**所有**历史对话
2. 不要让模型每次都读所有上下文
3. 上下文太长时**自动压缩**成 memory

如果只留一份数据，必然牺牲其中一条。所以拆成三层，各有各的生命周期：

| 层 | 存什么 | 谁在用 | 会不会被删 |
|---|---|---|---|
| **全量流水** `messages` | 每一条用户/小沃的话 + 时间戳 | 历史记录窗口 | 只有「清空对话记录」会删 |
| **上下文窗口** `BuildContext()` | 人设 + memory + **最近 6 轮** | 每次请求 | 不存，现拼现用 |
| **记忆摘要** `memory` | 旧对话压缩成 ≤150 字 | 作为 system 消息进上下文 | 每次压缩时被新摘要覆盖 |

关键点：**"记得住"和"读全部"是两件事**。模型看到的是「人设 + 一小段记忆 + 最近 6 轮」，
而用户翻历史看到的是全量流水 —— 两者互不影响。

### 压缩怎么触发

```
每轮回复结束后 → UncoveredCount >= 12 ？
   是 → 挑出「已压缩位置」之后、「最近 6 条」之前的消息
        → 交给 deepseek-chat 揉进已有记忆（提示词要求 ≤150 字、只留偏好/近况/约定）
        → 成功则 Covered 前移并落盘；失败就原样不动，等下次攒够再试
```

四个刻意的决定：

1. **压缩用 `deepseek-chat` 而不是用户当前选的模型**。压缩是机械劳动，不值得花 reasoner 的钱。
2. **失败静默**。没 Key、网络挂、余额不足都不弹窗 —— 后台任务不该打断聊天，旧消息留在流水里下次再试。
3. **留 6 条不压**。刚说的话被碾成摘要，语气和细节全丢，下一轮就接不上了。
4. **错误文案不入库**。`DeepSeekService` 出错时返回的是普通字符串，如果直接 append 进流水，
   下次压缩会把「网络请求失败：xxx」当成小沃说过的话记进长期记忆。所以 `IsErrorReply()` 先挡一道。

### 历史记录窗口

- 气泡右上角 `↺`（在收起键 `✕` 左边）
- 只读：不提供"从这里继续聊"，它是档案馆不是聊天框
- 顶部显示「小沃记得的事」——压缩结果对用户可见，这比黑箱更让人放心
- 没有记忆时整块隐藏，不占位置
- 打开自动滚到底：用户最想看的多半是最近说了什么

### 数据迁移

老版本的 `chat_history.json` 是一个纯数组，第一条塞的是 system 人设。
新的 `conversation.json` 结构变了，所以 `Load()` 里做了迁移：读旧文件 → 丢掉 system → 转成 `StoredMessage`（补当前时间）→
旧文件改名 `.bak` 留底。**只在新文件不存在时执行**，不会覆盖已有的新数据。

### 新增/改动文件

| 文件 | 说明 |
|---|---|
| `desktop/ConversationStore.cs` | **新增**。三层存储 + `BuildContext()` + `CompressAsync()` + `IsErrorReply()` + 旧数据迁移 |
| `desktop/HistoryWindow.xaml` / `.xaml.cs` | **新增**。只读历史窗口，含记忆块 |
| `desktop/MainWindow.xaml` | 气泡右上角加 `↺` 历史键，与 `✕` 并排 |
| `desktop/MainWindow.xaml.cs` | 对话全部改走 `ConversationStore`；回复后按需后台压缩 |

### 实测（同一个控制台冒烟工程）

```
流水 20 条 / 上下文 13 条（1 system + 12 最近）   ← 全量留存，但不全进请求
上下文最旧一条: 第8条                             ← 恰好是最近 6 轮
无 Key 时压缩：服务返回提示，CompressAsync 返回 false，数据不动
HistoryWindow ctor: OK
待压缩条数 20 / 需要压缩 True                      ← 阈值判断正确
迁移测试：20 条流水 → 读到旧 chat_history.json 后
  迁移后 2 条（system 被剔除）/ 旧文件已改名 / 内容为「旧问题」「旧回答」
```

### 没做但该知道的

- **压缩不可逆**：`memory` 覆盖式更新，旧摘要不会保留。想要"记忆时间线"得改成追加列表（成本更高）。
- **压缩没有并发保护跨进程**：同时开两个桌宠会互相覆盖 `conversation.json`。单人桌面场景可以接受。
- **`Covered` 是下标**，一旦将来允许删除单条历史，下标会错位。真要做删单条，得改成用消息 id 标记边界。
