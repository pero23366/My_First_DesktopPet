## 一、这一小步在做什么

一句话：**把首页那个按钮接上真东西 —— 点一下，小鲨鱼出场，并且带一套能用的最小控件。**

对齐 WPF 前作 `MainWindow.xaml` 的四块布局：

| WPF 前作 | 本次 Web 版 | 说明 |
|---|---|---|
| `ReplyBubble`（300×340，`#FFF9E6` + `#FFD700`） | `.pet__bubble` | 配色、尺寸直接沿用 |
| `PetImage`（254×275，`Stretch="Uniform"`） | `.pet__image`（`width:260px; height:auto`） | `height:auto` 就是 Web 的 `Uniform` |
| `SettingsButton` + `ModelToggleButton` | `#settingsBtn`（只保留设置） | 双模型切换要等后端，本步不做 |
| `ExitButton` / `InputBox` / `SendButton` | `#exitBtn` / `#inputBox` / `#sendBtn` | 一红一蓝圆形按钮照旧 |

**为什么用 SVG 而不是 PNG**：前作首帧 PNG 2.4MB，是明确要还的技术债。SVG 是向量，3KB、随便放大不糊、改颜色直接改代码，而且天然透明背景。

### 2.2 重点：为什么「先渲染、用 class 控制显隐」，而不是「点按钮才创建元素」

两种都能做到，差别在代价：

- **用 `class` 隐藏**：DOM 一次性建好。切换只是加/删一个类，改样式立刻生效。代价是初始多几十个节点（这里只有 10 来个）。
- **动态 `createElement`**：初始干净，但每次显示都要重建整棵树，并且**每次都得重新查一次节点、重新绑一次事件**，很容易漏。

WPF 里对应的是 `Visibility="Collapsed"`（前作的 `ReplyBubble` 就是这么干的）—— 这是同一种思路。本步选它，因为桌宠的 DOM 结构是**固定**的，不会随数据变成任意形状。

> 什么情况该反过来用动态创建？**数量不定**的东西，比如聊天消息列表本身 —— 见 `addMessage()`。

## 三、CSS/style.css

### 3.1 逐行表（本步新增部分）

| 选择器 / 行 | 在干什么 / 为什么这么写 |
|---|---|
| `.hidden { display: none !important; }` | **全站唯一显隐开关**。`!important` 是为了压过 `.pet { display:flex }` 这类声明 —— 不加的话 `.pet.hidden` 谁赢取决于书写顺序，是个定时炸弹 |
| `.pet { position: relative; display:flex; flex-wrap:wrap; ... }` | 两栏容器。`relative` 是给里面的 `.pet__settings` 当定位参照物（子元素 `absolute` 认最近的 `relative` 祖先） |
| `.pet__bubble { width:300px; height:340px; border-radius:16px; }` | 固定尺寸的对话框 —— 和前作 `Border Width="300" Height="340"` 一一对应 |
| `.pet__log { overflow-y:auto; display:flex; flex-direction:column; }` | 消息列表。`flex-direction:column` 让消息从上往下堆；`overflow-y:auto` 撑满后出滚动条（前作的 `ScrollViewer`） |
| `.pet__msg--me { align-self:flex-end; }` | 我说的话靠右。`align-self` 只影响**这一个**子项，不动整行 |
| `.pet__msg--pet { align-self:flex-start; }` | 小鲨鱼的话靠左 |
| `.pet__input { font-family:inherit; }` | 🔧 **表单控件不继承字体**，不写这行输入框会退成系统默认等宽字体，和页面其他文字不搭 |
| `.pet__icon { display:grid; place-items:center; border-radius:50%; }` | 圆形按钮 + 文字自动居中。圆形用 `50%`（不是 `999px`），因为按钮是正方形 |
| `.pet__settings { position:absolute; right:0; bottom:76px; }` | 悬浮在控件上方。`bottom:76px` 是让开底下那一行输入区 |
| `@media (max-width:680px)` | 窄屏时两栏自动上下排，气泡改全宽、变矮 |

### 3.2 重点：`.hidden` 为什么必须带 `!important`

CSS 里 `display` 是**同一个属性**，`!important` 的优先级高于一切普通声明（包括 `id` 选择器）。不写它的后果：

```css
.pet { display: flex; }        /* 特异性 0,1,0 */
.hidden { display: none; }     /* 特异性 0,1,0 —— 和上面打平 */
```

打平时**后写的赢**。你要是哪天把 `.hidden` 挪到 `.pet` 上面，隐藏功能就悄悄失效了 —— 而且没有报错，最难查的那种。

## 四、JS/main.js

### 4.1 分段说明

| 段 | 代码 | 在干什么 / 为什么这么写 |
|---|---|---|
| 1 | `const xx = document.querySelector('#xx')` ×10 | 模块加载时**只查一次**，之后回调里直接用变量。别在事件里反复 `querySelector` —— 那等于每次都遍历一遍 DOM |
| 2 | `function addMessage(text, from)` | 造一条消息：`createElement('li')` → 设 class → 设 `textContent` → `append` |
| 2 | `li.textContent = text` | ⭐ **不用 `innerHTML`**。用户输入 `<img onerror=...>` 会被 `innerHTML` 当成标签解析并执行 —— 这就是 XSS。`textContent` 一律当纯文本 |
| 2 | `chatLog.scrollTop = chatLog.scrollHeight` | 滚到底。`scrollHeight` 是内容总高，把滚动位置设成它 = 永远显示最新一条 |
| 3 | `home.classList.add('hidden')` / `pet.classList.remove('hidden')` | 生成：藏首页、显桌宠。反过来就是退出 |
| 3 | `if (chatLog.children.length === 0)` | 只在第一次登场时说那句话，来回切不重复刷屏 |
| 4 | `const text = inputBox.value.trim(); if (text === '') return` | 去空格后为空就不发。`trim()` 挡住「只敲了几个空格就回车」 |
| 4 | `inputBox.addEventListener('keydown', ...)` | 回车发送 |
| 4 | `if (event.isComposing) return` | ⭐ **中文输入法坑**。用拼音选词时按的回车是「上屏」，不是「发送」。`isComposing` 为 `true` 就说明还在拼，直接 return。这是前作 WPF 明确记录的技术债，这次一并还掉 |
| 5 | `settingsPanel.classList.toggle('hidden')` | 设置面板开关。`toggle` = 有就删、没有就加，一行搞定 |
| 5 | `chatLog.innerHTML = ''` | 清空对话。这里可以用 `innerHTML`，因为赋的是写死的空串，没有用户数据 |
| 6 | `let hideTimer = null` + `scheduleAutoHide()` | 10 秒后藏气泡。`clearTimeout` 先撤销上一次，否则连续发三条消息会挂三个计时器，先挂的照样触发 |
| 6 | `autoHideToggle.checked` | 每次计时前现读开关状态，所以关掉开关立刻生效，不用额外的监听 |

### 4.2 重点 A：`isComposing` 到底怎么判

`keydown` 事件里，用输入法拼「你好」时按回车，浏览器先给一个 `keydown`，此时：

- `event.isComposing === true` → 这是**选词确认**，不是发送
- 中文上屏结束后再按回车，`isComposing` 才是 `false`

前作 WPF 只判了 `e.Key == Key.Enter`，所以在中文输入法下会**误发送半截拼音**。这是同一个坑的两种语言版本。

### 4.3 重点 B：为什么 `exitBtn` 里能直接用 `hideTimer`

`hideTimer` 用 `let` 声明在文件靠下的位置，`exitBtn` 的监听写在它上面。看起来像「先用后声明」，但不会报错：

- `let` 的**暂时性死区（TDZ）** 只在**声明语句执行之前**生效
- 而这个回调是**用户点按钮时**才执行的，那时模块早就从头跑完、`hideTimer` 已经初始化好了

对比：如果是模块顶层直接 `console.log(hideTimer)` 写在声明之前，才会抛 `ReferenceError`。

### 4.4 重点 C：`setTimeout` 对标 WPF 的 `DispatcherTimer`

| WPF | JS |
|---|---|
| `new DispatcherTimer { Interval = 10s }` | `setTimeout(fn, 10000)` |
| `timer.Start()` | 调用 `setTimeout` 本身就开始了 |
| `timer.Stop()` | `clearTimeout(id)` |
| 单次执行要手动 `Stop()` | `setTimeout` **天生只跑一次**，不用停 |

差别：`setTimeout` 返回一个**数字 id**，你得自己存着才能取消 —— 所以才需要 `hideTimer` 这个变量。

## 六、总结

这一步真正学到的东西，按重要性排：

1. **`textContent` vs `innerHTML`** —— 用户输入进 DOM，默认用前者。这是安全意识，不是风格问题。
2. **`event.isComposing`** —— 中文输入法下判回车，必须加上这一句。
3. **`classList` + 一个 `.hidden` 类** —— 最省事的显隐方案，WPF 的 `Visibility` 在 Web 的等价物。
4. **`setTimeout` / `clearTimeout` 配对** —— 连续触发时先清再挂，否则计时器叠加。
5. **`let` 的 TDZ 只约束「执行到那一行之前」** —— 回调里引用下面的变量是安全的。
