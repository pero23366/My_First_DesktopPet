## 一、V1 范围（锁死）

### 做

| 项       | 具体要求                                                         |
| ------- | ------------------------------------------------------------ |
| **形象**  | 用户在本地选一张图当形象，**不上传到任何服务器**                                   |
| **人设**  | 结构化选项（性格 / 语气 / 口头禅 / 怎么称呼你）+ 自动拼成提示词 + **允许手改**             |
| **Key** | 用户填自己的 DeepSeek API Key，存 `sessionStorage`（关标签页即焚）           |
| **链路**  | 前端直连 `https://api.deepseek.com/chat/completions`（CORS 已实测放行） |
| **界面**  | 现有首页 + 桌宠页沿用；气泡、输入、设置面板都在                                    |
| **导出**  | 「下载配置」按钮，导出 `.pet.json`（人设 + base64 图），给桌面版导入用               |
| **运行**  | 纯静态，无后端，全部在浏览器里                                              |

### 不做（V1 明确排除）

- ❌ 文生图（形象只来自用户上传）
- ❌ 分享链接 / 上线发布（**延后**，等这条链路跑通再说）
- ❌ 走后端代理（ASP.NET Core 已冻结，不演进）
- ❌ 多桌宠管理、插件系统、社区
- ❌ 云端历史记录
- ❌ 第三方 CDN 脚本（见第一节末尾的安全规矩）

### 一条要立住的规矩

**V1 页面绝不引入任何第三方 CDN 脚本。**  
Key 存在浏览器里，同页面上任何一个脚本都能读到它。现在页面确实零外链脚本，保持住 —— 这是 BYO-Key 方案唯一的真实风险面。

## 二、这个选择带来的三个返工点

### ① 三帧待机动画要退役

用户上传的是**一张静态图**，没有 1→2→3 的帧序列。现有的 `@keyframes idle-frame-1/2/3` 和  
`.pet__frame--2/3` 上那两条手工 `transform` 补偿全部作废。

**换成单图呼吸感**：

```css
.pet__image { animation: breathe 3s ease-in-out infinite; }
@keyframes breathe {
  0%, 100% { transform: translateY(0) scale(1); }
  50%      { transform: translateY(-3px) scale(1.02); }
}
```

**意外收获**：`record/04` 里那个"三帧画布尺寸不一致导致大小跳"的 P1-1 问题，自动消失。

### ② `postChat()` 的契约整个换掉

|      | 现在（打自己后端）                 | 之后（打 DeepSeek）                                               |
| ---- | ------------------------- | ------------------------------------------------------------ |
| URL  | `localhost:5003/api/chat` | `https://api.deepseek.com/chat/completions`                  |
| 鉴权   | 无                         | `Authorization: Bearer <key>`                                |
| body | `{ message: "…" }`        | `{ model: "deepseek-chat", messages: [{role, content}, …] }` |
| 取值   | `data.reply`              | `data.choices[0].message.content`                            |

**但骨架原样保留**：`AbortController` 超时、`res.ok` 判断、两次 `await`、`finally` 清理，一行不改。

`messages` 里要带上人设：第一条固定是 `{ role: 'system', content: 人设提示词 }`，后面是历史对话。  
这就是为什么人设必须"能拼成一段文本"——它最终要变成 `system` 消息。

### ③ 设置面板语义变了

现在的「后端 API 地址 + 测试连接」，要改成「API Key + 模型名 + 测试」。  
测试方式也变：不再是 `GET /api/health`，而是**真发一句最短的话**（比如 `hi`，`max_tokens: 1`），  
因为 DeepSeek 没有"健康检查"接口。这一步顺带验证了 Key 是否有效。

## 四、两个待定 → 已拍板（2026-10-19 13:20）

### A · 图片存哪儿 —— **不持久化，但可导出**

用户决定：**不做浏览器持久化**。图片只活在当前会话里（`ObjectURL`），关掉浏览器就消失。  
同时提供一个「下载配置」按钮，把形象 + 人设导出成一个文件，将来桌面版直接导入。

| 方案                      | 刷新后 | 结论               |
| ----------------------- | --- | ---------------- |
| 只存内存（ObjectURL）         | ❌ 丢 | ✅ **选它**         |
| `localStorage` 存 base64 | ✅ 在 | ❌ 5MB 上限，一张大图就挤爆 |
| `IndexedDB` 存 Blob      | ✅ 在 | ❌ V1 不必要         |
| 上传到图床                   | ✅ 在 | ❌ 违背纯静态          |

**这个决定顺带解决了一个更大的问题** —— 见第五节。

### B · 流式输出 —— **先不做，单独一步加**

先把非流式的链路跑通（小步 8~15 不变），流式作为后续独立一步加上去。

理由：`ReadableStream` + `TextDecoder` + 边解边渲染是一整套新知识点，和"接上 DeepSeek"混在一起做，  
一旦出问题分不清是网络、鉴权、还是流解析。**先让一条路通，再加第二条。**

## 五、「下载配置」= 里程碑二的接口契约（意外收获）

本来「网页捏脸 → 桌面端读配置」在 PDF 里是一句带过、实际最重的话（我在风险清单里第 2 条提过）。  
「下载配置」这个按钮，**一次性把它解决了**：

```
网页端：捏脸 + 写人设  →  [下载 小狗.pet.json]  →  桌面端：拖进去 / 打开就行
```

**文件格式（定下来就别改，桌面端照这个读）**：

```json
{
  "format": "desktop-pet/1",
  "savedAt": "2026-10-19T13:20:00+08:00",
  "persona": {
    "name": "小狗",
    "options": { "性格": "温柔", "语气": "短句", "称呼": "你" },
    "prompt": "你是一只……（最终拼出来的那段 system 提示词）"
  },
  "image": "data:image/png;base64,...."
}
```

- `format` 带版本号：桌面端先看这个字段，不认识的版本直接拒绝并提示，而不是崩掉
- `prompt` 存**最终拼好的文本**，不存选项 —— 因为选项逻辑将来会改，存了最终结果，桌面端就不依赖网页的拼装规则
- `image` 内嵌 base64：单文件、无外部依赖。代价是体积（2MB 图 → 约 2.7MB 的 JSON），本地文件无所谓

**桌面端只需要做两件事**：读这个 JSON、把 `prompt` 当 system 消息、把 `image` 当形象。
