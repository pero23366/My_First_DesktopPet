## 一、这一小步在做什么

一句话：**证明「页面能打开 + CSS 能上色 + JS 能挂事件」这条链路是通的。**

三个文件各管一件事，职责不混 —— 这是后面所有代码的地基。

| 文件 | 唯一职责 | 对标 C# / WPF |
|---|---|---|
| `index.html` | 定义**结构**：页面上有什么元素 | `.xaml` 里的控件树 |
| `CSS/style.css` | 定义**外观**：元素长什么样 | XAML 里的 `Style` / 属性 |
| `JS/main.js` | 定义**行为**：元素被操作时干什么 | `.xaml.cs` 里的事件处理 |

这一版**刻意不写**的东西：桌宠 DOM、拖拽、聊天、fetch、后端。一步只做一件事。

### 2.2 为什么类名长成 `home__title` 这样（BEM）

`home__title` = 块(block) `home` + 元素(element) `title`，中间两个下划线。

**好处**：不用写 `.home .home__title` 这种后代选择器，一个类名就精确命中目标。
**代价**：类名变长。

如果写成 `.home h1 { … }`，将来在 `.home` 里再塞一个 `<h1>`，它会被无辜波及；而 `.home__title` 只命中明确标了这个类的那一个。

### 2.3 两个属性 + 一个 `type`

```html
<button id="createPetBtn" class="home__btn" type="button">生成桌宠</button>
```

- `id="createPetBtn"` —— JS 靠它找人，全页唯一，不能重复。
- `class="home__btn"` —— CSS 靠它上样式，可以给很多元素共用。
- `type="button"` —— **防雷属性**。不写的话浏览器默认是 `submit`。当前这页没有 `<form>`，所以看不出问题；但哪天把它包进表单，点一下就会**提交表单 + 刷新页面**，JS 里存的聊天状态全部丢失。现在写上，等于提前上保险。

### 2.4 `<script type="module">` 到底改了什么

```html
<script type="module" src="/main.js"></script>
```

**① `type="module"`** 让浏览器按 ES Module 解析，带来三个副作用：

| 副作用 | 后果 | 对本项目的意义 |
|---|---|---|
| 自动 `defer` | 等 HTML 解析完才执行脚本 | 所以 `main.js` 里可以直接 `querySelector`，不用监听 `DOMContentLoaded` |
| 独立作用域 | 模块里的变量**不挂到 `window`** 上 | 命名不污染全局，多个文件互不干扰 |
| 支持 `import` / `export` | 可以把代码拆成多个文件互相引用 | 这是后面拆文件的入场券（准则里的「半步缺口」） |

另外，module 模式自动开启严格模式（`'use strict'`），一些静默出错的写法会直接抛异常。

**② `src` 开头那个 `/`** 不是相对当前文件，而是**从站点根**算。
Vite dev server 的站点根 = `index.html` 所在目录（`My_First_DesktopPet/`）。所以 `/main.js` 找的是**根目录下的** `main.js`，而不是 `JS/main.js`。

**③ 为什么放在 `<body>` 末尾**
老习惯：早年没有 `defer`，脚本一执行就会阻塞解析，放末尾能保证 DOM 已经建好。
现在有了 `type="module"` 的 `defer`，放 `<head>` 里也行，但放末尾依然是最不费脑子的写法。

### 3.2 为什么全局打开 `box-sizing: border-box`

CSS 默认是 `content-box`：

```css
/* content-box 下 */
width: 200px;    /* 仅内容区 200px */
padding: 20px;   /* 左右各 20 → 实际总宽 200 + 40 = 240px */
border: 2px;     /* 再加 4 → 实际总宽 244px */
```

写的是 200，量出来是 244 —— 布局计算全靠心算，非常容易翻车。

改成 `border-box` 后：

```css
/* border-box 下 */
width: 200px;    /* 这就是含 padding 和 border 的总宽，永远是 200 */
```

**写多少就是多少**，这是让布局「可预测」的总开关。几乎所有现代项目都会在 `*` 上全局打开它。

### 3.3 为什么按钮上必须写 `font-family: inherit`

`<button>`、`<input>`、`<select>`、`<textarea>` 这类**表单控件不继承**父元素的字体 —— 浏览器给它们准备了一套自己的默认字体（常见是宋体 / Arial）。

不写这行，你会看到：页面正文是微软雅黑，按钮上的字却是另一种字体，一眼能看出「不是一套的」。
`color` 同理，所以 47 行还要单独给 `#fff`。

### 3.4 `body` 的 flex 居中和 `.home` 的 `text-align` 不能互相替代

两件事：

- `body { display:flex; align-items:center; justify-content:center }` —— 管的是 **`.home` 这个盒子摆在页面的哪个位置**（居中）。
- `.home { text-align: center }` —— 管的是 **`.home` 盒子内部的文字和按钮怎么排**（居中）。

盒子摆中间 ≠ 盒子里的字就自动居中。所以两处都写了。

### 3.5 `padding` 的两值 / 四值写法

```css
padding: 12px 40px;              /* 上下 12 / 左右 40 */
padding: 12px 40px 8px;          /* 上 12 / 左右 40 / 下 8 */
padding: 12px 40px 8px 24px;     /* 上 12 / 右 40 / 下 8 / 左 24 —— 顺时针 */
```

写反了视觉上通常也不会报错，只是「按钮看着怪怪的」—— 属于要靠肉眼抓的错。

### 3.6 `border-radius: 999px` 为什么不是 `50%`

- `border-radius: 999px` —— 圆角半径远大于盒子高度时，浏览器会自动收敛成**两边半圆**，得到标准胶囊形。无论按钮多高多扁都成立。
- `border-radius: 50%` —— 百分比是按**宽度**和**高度分别**算的。盒子是扁的（比如 140×40），就会变成**椭圆**，不是胶囊。

### 3.7 `transition` 写在哪一侧决定了「有没有来回」

`transition` 定义在**哪个状态**，从该状态**离开/进入**时才应用：

| 写法 | 效果 |
|---|---|
| 写在 `.home__btn`（常态） | 鼠标移入有过渡，**移出也有过渡** |
| 写在 `.home__btn:hover` 里 | 只有移入有过渡，移出会**瞬间跳回** |

所以本项目写在常态块里（52 行），`:hover` 里只写「变成什么样」（56–57 行）。

### 4.2 `querySelector` 与它的 null 陷阱

```js
const createPetBtn = document.querySelector('#createPetBtn')
```

- 参数是 **CSS 选择器字符串**：`'#id'`、`'.class'`、`'div > p'` 都能用。
- 返回第一个匹配元素，**找不到返回 `null`**。
- 对标 WPF：`FindName("createPetBtn")`（对应 XAML 里的 `x:Name`）。

**危险在于没有类型检查**：C# 里至少 `null` 会逼你想着判空；纯 JS 没有编译器提醒你。
哪天 `id` 打错一个字母 → 返回 `null` → 下一行 `null.addEventListener` → 直接 `TypeError`，页面白屏。

所以后面加功能时，只要有「靠 id 找人」的地方，就要意识到这一步可能拿到 `null`。

### 4.3 `addEventListener` 对标 C# 的事件

```js
createPetBtn.addEventListener('click', () => { … })
```

对应 C#：

```csharp
createPetBtn.Click += (s, e) => { … };
```

| 差异 | C# | JS |
|---|---|---|
| 订阅方式 | `+=` 委托链，一个事件一个处理链 | 可给同一元素挂**任意多个** `click` 监听，**全部都会执行** |
| 事件名 | 编译期检查，拼错直接编译不过 | **字符串**，拼错不报错，只是永远不触发（静默失败） |
| 阶段 | 只有冒泡 | 有**捕获 / 冒泡**两阶段，第三参 `true` 走捕获 |
| 取消 | `-=` 解除 | `removeEventListener`，且**必须传同一个函数引用**，匿名箭头函数解不掉 |

回调 `() => { … }` 是箭头函数，对标 lambda。箭头函数不绑定自己的 `this`，而是继承外层 —— 这点反而比 C# 的 lambda 直觉更接近「捕获外部变量」。

### 4.4 为什么这里不用等 `DOMContentLoaded`

因为 19 行写了 `type="module"`，浏览器会自动 `defer`：等 HTML 全部解析完才执行脚本，此时 `#createPetBtn` 一定已经在 DOM 里了。

如果哪天把 `type="module"` 去掉、又把 `<script>` 挪回 `<head>`，`querySelector` 就会拿到 `null` —— 这是很经典的一对连环坑。

## 五、这一版已知的 3 个断点

目录从「四个文件平铺」重排成 `CSS/`、`JS/`、`JSON/` 之后，有三处路径没跟着改：

| # | 位置 | 现状 | 应该 | 后果 |
|---|---|---|---|---|
| 1 | `index.html:8` | `href="../CSS/style.css"` | `href="CSS/style.css"` | 回退一级是 `My First DesktopPet/`，那层没有 `CSS/` → 样式表 404，页面无样式 |
| 2 | `index.html:19` | `src="/main.js"` | `src="/JS/main.js"` | 站点根下已无 `main.js` → 脚本 404，JS 完全不执行 |
| 3 | `JSON/package.json` | 被移进 `JSON/` | 搬回项目根（与 `index.html` 同级），`package-lock.json` 一起 | `npm run dev` 在根目录找不到 package.json；Vite 也会把 `JSON/` 当根目录 |

### 怎么自己验证第 2 条

1. `npm run dev` 打开页面
2. F12 → Network 面板 → 刷新
3. 看到 `main.js` 是红色 404
4. 点「生成桌宠」按钮 → Console 里那句提示**不会出现**

这就是「路径错了」最直白的证据。修好后同一套动作再做一遍，应该看到 200 和那句日志。

## 六、总结

### 这一步真正学到的

1. **三个文件三种职责**：结构 / 外观 / 行为，不混。这是后面能拆得开的前提。
2. **`id` 归 JS，`class` 归 CSS** —— 一个身份，一套衣服。
3. **`type="module"` 不只是「能用 import」**，它还带来 `defer` 和独立作用域，直接改变了「脚本什么时候能拿到 DOM」。
4. **`box-sizing: border-box` 是布局可预测的总开关**，不是可选的美化项。
5. **表单控件的字体和颜色不继承**，按钮上必须显式写 `font-family: inherit`。
6. **纯 JS 没有类型检查**：`querySelector` 返回 `null`、事件名写错，都不报错，只会静默失败。

### 留到后面的

- 三处断点修复（等用户确认由谁改）
- 桌宠舞台 DOM + 「生成桌宠」的真实行为
- `fetch` / `Promise` / `async·await`（唯一红灯缺口，必须拆到原理层讲）
