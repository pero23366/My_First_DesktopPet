| 行 | 代码 | 在干什么 |
|---|---|---|
| 4 | 注释 | 说明"一次性抓齐"的两个好处：DOM 只查一次、一眼能看出这步动了哪些元素 |
| 6–9 | 4 个**容器级**节点 | `home` 首页、`pet` 桌宠、`bubble` 气泡、`chatLog` 消息列表 |
| 11–14 | 4 个**动作**节点 | 生成按钮、退出按钮、输入框、发送按钮 |
| 16–19 | 4 个**设置**节点 | 设置按钮、面板本体、自动隐藏开关、清空按钮 |

**三组之间的空行是有意义的**：容器 / 动作 / 设置，分组比一长串不空行好读。

**为什么放在最外层而不是函数里**：`querySelector` 每次都要遍历 DOM，写成模块级常量只查一次。
这也是 `type="module"` 带来的好处之一 —— 模块在 HTML 解析完才执行，此刻节点一定已经存在。

## 二、分区 2：`addMessage`（21–32 行）

```js
function addMessage(text, from) {
  const li = document.createElement('li')
  li.className = 'pet__msg pet__msg--' + from
  li.textContent = text
  chatLog.append(li)

  bubble.classList.remove('hidden')
  chatLog.scrollTop = chatLog.scrollHeight

  return li
}
```

| 行 | 代码 | 在干什么 / 为什么 |
|---|---|---|
| 22 | `function addMessage(text, from)` | 两个参数：内容、说话人（只允许 `'me'` / `'pet'`） |
| 23 | `document.createElement('li')` | 建一个 `<li>` 节点。**注意此刻它还没进页面**，是个游离节点 |
| 24 | `li.className = 'pet__msg pet__msg--' + from` | 基础类 + 修饰类。`from='me'` → `pet__msg--me`（蓝底靠右），`'pet'` → `pet__msg--pet`（白底靠左） |
| 25 | `li.textContent = text` | ⭐ **用 `textContent` 不用 `innerHTML`**：用户输入 `"<img src=x onerror=alert(1)>"` 时，`textContent` 会把它当纯文字显示；`innerHTML` 会真的当 HTML 执行 —— 这就是 XSS |
| 26 | `chatLog.append(li)` | 把节点挂进页面。`append` 比 `appendChild` 新，能一次塞多个、也能塞字符串 |
| 28 | `bubble.classList.remove('hidden')` | 有新消息就把气泡"叫醒"（它可能被 10 秒自动隐藏收起来了） |
| 29 | `chatLog.scrollTop = chatLog.scrollHeight` | 滚到底。`scrollHeight` 是内容总高，赋给 `scrollTop` 就是滚到最底。**这一行会强制浏览器立刻算一次布局**，能拿到刚 append 的新高度 |
| 31 | `return li` | ⭐ 这一轮新加的。把刚建出来的节点交给调用方，后面可以**就地改它的文字** |

**`return li` 的意义**：`send()` 里先放一个 `…` 占位，等后端回来直接改这个 `li` 的 `textContent`，
不用"删一个再加一个"。少一次 DOM 增删，也不会让滚动位置跳一下。

| 行 | 代码 | 在干什么 |
|---|---|---|
| 48 | `pet.classList.add('hidden')` | 桌宠藏起来 |

| 50 | `home.classList.remove('hidden')` | 回首页 |
| 51 | `inputBox.value = ''` | 清掉没发出去的半句话 |
| 52 | `clearTimeout(hideTimer)` | 撤销还在倒计时的"10 秒后隐藏"，别让它在你回首页之后才触发 |

**这里有个 TDZ 的坑，但没炸**：`hideTimer` 在 52 行被引用，而它的 `let hideTimer = null` 写在 136 行。

听起来违反了"`let` 不能先用后声明"，但实际不会报错，原因是：
**这个 arrow function 只是"被注册"，并没有"被执行"**。模块顶层代码是同步一路跑完的 —— 跑到 136 行时 `hideTimer` 就初始化好了。
真正执行 52 行，是在用户点击按钮的那一刻，那时早过了初始化。所以 `let` 的暂时性死区（TDZ）只约束**同步执行期**，管不到回调。

## 四、分区 4：发消息（55–124 行）—— 全文件核心

### 4.1 `send()`（56–84 行）

```js
let isSending = false

async function send() {
  const text = inputBox.value.trim()
  if (text === '') return
  if (isSending) return

  addMessage(text, 'me')
  inputBox.value = ''
  scheduleAutoHide()

  const pending = addMessage('…', 'pet')
  setBusy(true)

  try {
    pending.textContent = await postChat(text)
  } catch (err) {
    pending.textContent =
      err.name === 'AbortError'
        ? '（想太久了……先不说这个）'
        : '（我连不上后端，去设置里看看 API 地址）'
    console.error('发送失败：', err)
  } finally {
    setBusy(false)
    scheduleAutoHide()
  }
}
```

| 行     | 代码                                           | 在干什么 / 为什么                                                                                                               |
| ----- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 56    | `let isSending = false`                      | 模块级状态位。`let` 不是 `const`，因为它要变                                                                                            |
| 58    | `async function send()`                      | 标成 `async` 才能在里面用 `await`。**它本身返回一个 Promise**（这次没人接，所以 `send()` 内部若抛未捕获异常会变成 unhandled rejection —— 好在 `try/catch` 全覆盖了） |
| 59    | `inputBox.value.trim()`                      | 取内容并去掉首尾空白                                                                                                               |
| 60    | `if (text === '') return`                    | 空消息不发。**只敲空格也算空**                                                                                                        |
| 61    | `if (isSending) return`                      | 上一句还没回来，忽略这次。**第一道防连击**                                                                                                  |
| 63    | `addMessage(text, 'me')`                     | ⭐ **乐观更新**：先把自己说的话上屏，不等后端                                                                                                |
| 64    | `inputBox.value = ''`                        | 立刻清空输入框，用户能马上打下一条                                                                                                        |
| 65    | `scheduleAutoHide()`                         | 从"发送这一刻"起算 10 秒                                                                                                          |
| 68    | `const pending = addMessage('…', 'pet')`     | ⭐ 放占位气泡，并把节点存进 `pending`                                                                                                 |
| 69    | `setBusy(true)`                              | 锁住输入框和发送键                                                                                                                |
| 72    | `pending.textContent = await postChat(text)` | ⭐ **await 挂起函数，等后端那句话回来**，然后就地改文字                                                                                        |
| 73    | `catch (err)`                                | 失败分支                                                                                                                     |
| 75–78 | 三元表达式                                        | 区分两种失败：自己掐断的超时 vs 其它（网络 / CORS / 后端没起）                                                                                   |
| 79    | `console.error('发送失败：', err)`                | 准则 §四技术债 #7 的修复：**不再静默吞异常**                                                                                              |
| 81    | `setBusy(false)`                             | 解锁                                                                                                                       |
| 82    | `scheduleAutoHide()`                         | 从"回复到达"这一秒重新计 10 秒 —— 这样用户有完整 10 秒看回复                                                                                    |

**`finally` 为什么必须写**：成功要走解锁、失败也要走解锁。写在 `finally` 里就两条路都覆盖，
不用在 `try` 末尾和 `catch` 末尾各抄一遍。

### 4.2 `setBusy()`（86–92 行）

```js
function setBusy(busy) {
  isSending = busy
  inputBox.disabled = busy
  sendBtn.disabled = busy
  if (!busy) inputBox.focus()
}
```

| 行 | 代码 | 在干什么 |
|---|---|---|
| 88 | `isSending = busy` | 逻辑锁（给 `send` 里的 `if` 用） |
| 89 | `inputBox.disabled = busy` | 视觉 + 交互锁：输入框变灰、不能输入 |
| 90 | `sendBtn.disabled = busy` | 发送键也锁上 |
| 91 | `if (!busy) inputBox.focus()` | 解锁时把光标还回去，用户可以接着聊 |

**为什么逻辑锁和 DOM 锁都要**：`disabled` 已经能挡住点击，但 `isSending` 还能挡住"回车发送"
（回车和点击是两条不同的路径，前者不经过 `disabled` 的按钮）。

### 4.3 `postChat()`（94–116 行）

```js
async function postChat(message) {
  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), 15000)

  try {
    const res = await fetch(getApiBase() + '/api/chat', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message }),
      signal: controller.signal,
    })

    if (!res.ok) throw new Error('HTTP ' + res.status)

    const data = await res.json()
    return data.reply
  } finally {
    clearTimeout(timer)
  }
}
```

| 行   | 代码                                                | 在干什么 / 为什么                                                                                                                 |
| --- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 96  | `new AbortController()`                           | 造一个"中止开关"。它身上带一个 `signal`（信号），谁拿着都能随时喊停                                                                                    |
| 97  | `setTimeout(() => controller.abort(), 15000)`     | 15 秒后自动按开关。⭐ **`fetch` 本身没有超时机制** —— 后端不响应时它会一直挂着，界面永远转                                                                    |
| 100 | `await fetch(url, {...})`                         | 发请求。**第一个 `await`**：等"响应头回来了"                                                                                              |
| 101 | `method: 'POST'`                                  | 默认是 GET，这里必须显式写                                                                                                            |
| 104 | `headers: { 'Content-Type': 'application/json' }` | 告诉后端"我发的是 JSON"。⭐ 同时**这个头会让请求超出"简单请求"的范围，从而触发 CORS 预检**                                                                    |
| 105 | `JSON.stringify({ message })`                     | JS 对象 → JSON 字符串。⭐ 键名 `message` 要和后端 `ChatRequest.Message` 对上（JSON 绑定不区分大小写）                                               |
| 106 | `signal: controller.signal`                       | 把这个请求和中止开关绑在一起                                                                                                             |
| 109 | `if (!res.ok) throw ...`                          | ⭐ `fetch` **只在网络层失败时 reject**。后端返回 400 / 500 时它是 resolve 的 —— 所以必须自己看 `res.ok`（200–299 才是 true）。这正是 WPF 前作技术债 #4「不看状态码」的修复 |
| 111 | `const data = await res.json()`                   | **第二个 `await`**：把响应体读出来并解析。`fetch` resolve 时 body 可能还没到，所以这里又是一个 Promise                                                   |
| 112 | `return data.reply`                               | 后端属性是 `Reply`，JSON 序列化自动变 `reply`                                                                                          |
| 114 | `clearTimeout(timer)`                             | 请求已经结束（不论成败），15 秒的闹钟没必要留着。**不清的话，它会在 15 秒后对一个已经结束的请求调用 `abort()`**                                                         |

### 4.4 两个入口（118–124 行）

```js

inputBox.addEventListener('keydown', (event) => {

  if (event.key === 'Enter') send()
```

## 六、分区 6：气泡自动隐藏（135–144 行）

```js
let hideTimer = null

function scheduleAutoHide() {
  clearTimeout(hideTimer)
  if (!autoHideToggle.checked) return
  hideTimer = setTimeout(() => {
    bubble.classList.add('hidden')
  }, 10000)
}
```

| 行 | 代码 | 在干什么 / 为什么 |
|---|---|---|
| 136 | `let hideTimer = null` | 存定时器 ID。`setTimeout` 返回的是一个数字 ID，拿它才能撤销 |
| 139 | `clearTimeout(hideTimer)` | ⭐ **先撤销上一次**。不撤销的话，连发 3 条消息会有 3 个定时器同时在跑，气泡会在第一个到时就被藏起来 |
| 140 | `if (!autoHideToggle.checked) return` | 设置里关了自动隐藏就什么都不做 |
| 141 | `hideTimer = setTimeout(...)` | 起一个新的 10 秒倒计时，并把 ID 存回去 |
| 142 | `bubble.classList.add('hidden')` | 时间到，藏气泡 |

**函数名用 `schedule`（安排）而不是 `hide`**：因为它不是"立刻隐藏"，而是"重新安排一次隐藏"。命名准确，读代码的人不会误解。

> `clearTimeout(null)` 是完全合法的，不会报错 —— 所以第一次调用时 `hideTimer` 是 `null` 也没关系。

### 7.2 地址规整（156–165 行）

```js
function normalizeBase(raw) {
  return raw.trim().replace(/\/+$/, '')
}

function getApiBase() {
  return normalizeBase(apiBaseInput.value) || API_DEFAULT
}
```

| 行 | 代码 | 在干什么 |
|---|---|---|
| 157 | `normalizeBase(raw)` | `trim()` 去首尾空格 |
| 158 | `.replace(/\/+$/, '')` | 正则：`\/+` 一个或多个斜杠，`$` 锚定结尾 → **去掉所有结尾斜杠**。否则会拼出 `http://host//api/health`（多一个斜杠，有的服务器会 404） |
| 163–164 | `getApiBase()` | ⭐ **单一来源**：发消息和测试连接都调它，两边不会算出不同地址 |

> ⚠️ 这个函数**不补协议**。用户填 `localhost:5003`（漏 `http://`）时，`fetch` 会把它当成未知协议直接抛 `TypeError`，最后被显示成"连不上后端" —— 误诊。

### 7.3 状态提示（167–171 行）

```js
function showApiStatus(text, ok) {
  apiStatus.textContent = text
  apiStatus.classList.toggle('pet__api-status--ok', ok === true)
  apiStatus.classList.toggle('pet__api-status--err', ok === false)
}
```

| 行 | 代码 | 在干什么 |
|---|---|---|
| 168 | `textContent = text` | 换文案 |
| 169–170 | `classList.toggle(cls, force)` | ⭐ **第二参数是"强制开关"**：传 `true` 就加上、`false` 就移除。比 if/else 干净得多 |

**为什么传 `ok === true` 而不是直接传 `ok`**：调用时会传 `null`（"连接中"），这时两个 `toggle` 都拿到 `false`，
两个颜色类都被摘掉 → 回到默认灰色。如果直接传 `ok`，`null` 会被当成 falsy 也算 false 没问题，
但写 `=== true` 语义更明确：**只有明确是 true 才是绿色**。

## 九、这一版查出的 4 个真问题

### ① 后端慢于 10 秒时，回复永远看不见（新发现，竞态）

时序：

```
0s    send()：scheduleAutoHide() → 10 秒后藏气泡
0s    await postChat(...) 挂起
10s   定时器到 → bubble 被加上 .hidden
12s   回复到达 → pending.textContent = 回复   ← 只改文字，没人叫醒气泡
12s   finally：scheduleAutoHide() 重新计时    ← 但气泡已经是隐藏的
```

结果：用户盯着屏幕，气泡在 10 秒时消失，回复到了却看不见。

**修法**：成功拿到回复时把气泡叫回来

```js
pending.textContent = await postChat(text)
bubble.classList.remove('hidden')
```

### ② HTTP 错误被误诊成"连不上"

109 行 `throw new Error('HTTP ' + res.status)` 抛出的错误 `name === 'Error'`，
落到 76 行的三元里只会走 `else` 分支 → 显示"我连不上后端"。
可实际情况是**连上了、后端明确说了 400**（比如消息超长）。查错方向会被带偏。

**修法**：给这类错误打个标记

```js
if (!res.ok) {
  const e = new Error('HTTP ' + res.status)
  e.isHttpError = true
  throw e
}
```

`catch` 里先判 `err.isHttpError`，显示"后端返回了 400"。

### ③ 请求进行中退出，焦点会被抢到隐藏的输入框

请求没回来时点 ✕ 退出 → `pet` 被 `hidden`，但 `postChat` 还在跑。
回到首页后 `finally` 里的 `setBusy(false)` 会执行 `inputBox.focus()` —— 把焦点塞进一个已经看不见的输入框。

**修法**：`setBusy(false)` 前判断一下视图是否还开着，或干脆在 `exitBtn` 里把 `isSending` 复位。

### ④ `disabled` 没有任何视觉反馈

`inputBox` 和 `sendBtn` 被禁用后，CSS 里没有 `:disabled` 样式，**看起来和正常状态一模一样**。
用户会以为还能点。

**修法**（加在 `common.css`）：

```css
.pet__icon:disabled,
.pet__input:disabled {
  opacity: 0.5;
  cursor: not-allowed;
}
```

## 十、总结

**这份文件的骨架是健康的**：

- 所有渲染只走 `addMessage` 一个出口，没有第二处拼 DOM
- 所有后端地址只走 `getApiBase` 一个出口，没有第二处拼 URL
- 失败路径有 `console.error`，不静默吞
- `finally` 负责解锁和重新计时，成功失败都不漏

**最值得记住的三件事**：
1. `fetch` 既不超时、也不为 4xx/5xx reject —— 这两件都得自己补
2. 乐观更新要配套"对账"，否则等待期间状态会错位（第 ① 个 bug 就是漏了对账的一半）
3. `return li` 这种"把新节点交出去"的写法，让"原地替换"变成了可能，比"删一个再加一个"稳
